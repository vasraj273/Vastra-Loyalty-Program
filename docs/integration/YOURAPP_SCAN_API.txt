==========================================================
 LOYALTY SCAN API  —  for the YourApp backend team
==========================================================

Three APIs for scanning loyalty QR codes from YourApp
(preview a code, redeem it, read a retailer's balance).
Call them from your BACKEND SERVER only — the API key must
never be put inside the mobile app.

Base URL:
    https://vastra-loyalty.onrender.com

Headers (required on all three APIs):
    Content-Type : application/json
    X-API-Key    : <secret key — shared with you privately>

All requests and responses are JSON.
Every error looks like:
    { "detail": "<message>", "status": false }


----------------------------------------------------------
 "status" — DID THE CALL WORK?
----------------------------------------------------------

EVERY response from these APIs carries a boolean "status":

    status: true   -> the call worked. We answered you.
    status: false  -> the call did not work.

It is there so you can tell "the API is fine, there is just
no data / the code was already used" apart from "the API
failed", without reading the HTTP code. The HTTP codes are
UNCHANGED — a 404 is still a 404. This is a second, easier
signal, never a replacement.

Two things to keep straight:

1. "status" is ONLY the boolean. A code's own
   redeemed/available state is reported as "qrStatus", on
   /yourapp/qr/lookup only. (That field used to be called
   "status"; it was renamed when the boolean took the name.
   If you integrated before Aug 2026, this rename is the
   only field change you need to make.)

2. An ALREADY-REDEEMED code is a SUCCESSFUL call. Lookup
   answers status: true with qrStatus: "redeemed".
   status: false means we failed to answer — not that the
   answer was "no".

status: false also comes back on failures that happen
before we even look at your request — a wrong X-API-Key
(401), the integration switched off (503), a rate limit
(429), a malformed body (422) — and on an unhandled crash
on our side, which answers
    500 { "detail": "Internal server error", "status": false }
instead of dropping the connection. That last case is the
one this flag exists for.


----------------------------------------------------------
 API 1 — PREVIEW A CODE  (optional, before redeeming)
----------------------------------------------------------

    POST /yourapp/qr/lookup

Tells you what a code is worth and whether it was already
scanned. Read-only — it never redeems anything, so it is
safe to call every time the camera reads a QR.

REQUEST BODY:

    {
      "code": "3f9c2a..."
    }

"code" = the token at the end of the QR link
(.../web/scan/<token>), OR the 6-character manual code
printed under the QR. Dashes, spaces, and small/capital
letters do not matter.

RESPONSE (200 OK):

    {
      "qrStatus": "available",
      "is_box": false,
      "items": 1,
      "product": {
        "external_id": "VP-9281",
        "name": "Silk Saree",
        "sku": "SS-001"
      },
      "base_points": 50,
      "bonus_points": 25,
      "total_points": 75,
      "scheme": { "id": 2, "name": "Diwali Bonus" },
      "redeemed_at": null,
      "redeemed_by_shop": null,
      "status": true
    }

Notes:
- "qrStatus" becomes "redeemed" once the code is scanned;
  then "redeemed_at" and "redeemed_by_shop" are filled in.
  "status" stays true either way — a redeemed code is
  still a successful lookup.
- Points are PER ITEM. For a box sticker ("is_box": true),
  each of the "items" children earns "total_points"
  (example: a 12-item box = 12 x total_points).
- "bonus_points" shows the bonus active right now; the
  final bonus is decided at the moment of the real scan.


----------------------------------------------------------
 API 2 — REDEEM A SCAN  (this one gives the points)
----------------------------------------------------------

    POST /yourapp/scan

REQUEST BODY:

    {
      "phone": "+91 98765 43210",
      "code":  "3f9c2a...",
      "lat":   26.9124,
      "lng":   75.7873
    }

Field by field:
- "phone" : the retailer's registered mobile number in
            YourApp. We match on the LAST 10 DIGITS, so
            +91, a leading 0, spaces and dashes are all
            fine.
- "code"  : same as API 1 (QR token or manual code).
- "lat" / "lng" : optional. The GPS location of the scan,
            as two separate decimal numbers. Please send
            them when available — they power the
            manufacturer's scan map.

RESPONSE (200 OK):

    {
      "redeemed": true,
      "is_box": false,
      "items_registered": 1,
      "product": {
        "external_id": "VP-9281",
        "name": "Silk Saree",
        "sku": "SS-001"
      },
      "points_awarded": 75,
      "base_points": 50,
      "bonus_points": 25,
      "scheme": { "id": 2, "name": "Diwali Bonus" },
      "retailer": {
        "id": 12,
        "shop_name": "Kumar Sarees",
        "region": "Jaipur"
      },
      "new_balance": 555,
      "status": true
    }

Show "points_awarded" and "new_balance" to the retailer as
the success screen. For a box, "items_registered" = number
of items credited, and the points fields are totals across
all of them. The scan reports its own outcome through
"redeemed", as it always has — there is no "qrStatus" here.


----------------------------------------------------------
 API 2b: GET A RETAILER'S TOTAL POINTS
----------------------------------------------------------

    POST /yourapp/points

Returns just the retailer's current points balance, nothing
else. Identified by phone (same matching as the scan call).
Read-only.

Request:

    { "phone": "+91 98765 43210" }

Response 200:

    { "total_points": 555, "status": true }

- "total_points" is the live wallet balance (scans earned
  minus gifts redeemed, etc.), always current.
- No code here, so the phone is matched across ALL
  manufacturers. If the same phone is registered to two
  retailers we return 409 (report it) instead of guessing.

Errors: 403 "Phone number not registered", 403 "Account is
blocked", 409 "Multiple retailers share this phone number",
422 "Invalid phone number", 401 "Invalid API key",
503 "YourApp integration is not configured".


----------------------------------------------------------
 ERRORS TO HANDLE
----------------------------------------------------------

Every one of these carries "status": false next to
"detail", so checking !body.status is enough to route into
your error path.

HTTP 404  "Invalid code"
    The code does not exist (or belongs to another brand).
    Show: "This code isn't valid."

HTTP 409  "Code already redeemed" / "Box already redeemed"
    Already scanned earlier. A normal situation, not a bug.
    (Use API 1 to see who scanned it and when.)

HTTP 403  "Phone number not registered"
    This phone is not onboarded under the code's
    manufacturer. Show: "Your shop isn't set up for
    rewards yet — contact the manufacturer."

HTTP 403  "Account is blocked"
    The retailer was disabled by the admin.

HTTP 409  "Multiple retailers share this phone number"
    A data problem on our side — report it to us.

HTTP 422  "Invalid phone number"
    Fewer than 10 digits after cleanup.

HTTP 401  "Invalid API key"
    Wrong or missing X-API-Key header. A config problem —
    fix the key, do not retry as-is.

HTTP 503  "YourApp integration is not configured"
    The key is not set on our server — contact us.

HTTP 429  (rate limited)
    Too many calls too fast. Wait a moment and retry
    (the Retry-After header is preserved).

HTTP 500  "Internal server error"
    Something broke on our side. Safe to show "please try
    again"; report it to us if it keeps happening.


----------------------------------------------------------
 IMPORTANT NOTES
----------------------------------------------------------

1. Do NOT blind-retry the scan call after a timeout —
   first call API 1 (lookup) to check whether the scan
   actually went through.

2. QR codes never expire. Only the bonus schemes are
   time-bound (the bonus simply becomes 0 when no scheme
   is active).

3. A code can be credited only ONCE, ever. Duplicate /
   simultaneous scans are rejected by our server.

4. The X-API-Key must stay on your backend server only.
   Never ship it inside the Android/iOS app.
